ChaosLab is a local prototype built around a saved recording. It is not a
production fault-injection service, and it has not been run against anything
outside its own Docker Compose sandbox.

## Architecture Overview

The operator selects a fault. The controller uses the saved dependency map to
predict impact, checks a healthy baseline, and injects one bounded fault into an
allowlisted service. Locust signals and an owner-data probe feed the watchdog, and
the resulting run record and dependency snapshot feed read-only reports. The
`demo` link above opens the published dependency map; the resilience dashboard is
in the repository.

## What's Built

- **Dependency analysis**: A map combining source-backed PetClinic semantics with Docker Compose, Eureka, Prometheus, Zipkin, and Locust observations, with uncertain and stale evidence labelled
- **Qualitative prediction**: Which user actions become unavailable or degraded for a selected service failure, including gateway fallbacks
- **Controlled injection**: Crash, freeze, network delay, packet loss, CPU starvation, and traffic spike against allowlisted local services
- **Safety and recovery**: Healthy-baseline check, watchdog thresholds, a kill switch, and a dead-man's switch
- **Measured outcomes**: Per-run timelines and audit events, plus a comparison of predicted and observed responses

## What's Next

- **AI planner and analysis agent**: Described in the repository as planned; the current controller provides the safety boundary and evidence they would use
- **Re-record the Visits run**: The committed recording predates the canary-visit check and still shows "recovery not confirmed"
- **Fresher map**: The published dependency map is a snapshot, so runtime observations become stale as time passes
