problem: >-
  The Magic Mouse has a touch surface, but macOS only uses it to scroll, so a
  one-finger brush while clicking or resting your hand scrolls the page. I wanted
  the surface to behave like a tiny trackpad instead: small cursor moves without
  moving the mouse, scrolling only on purpose with two fingers, and taps that
  click.

  - >-

    source has to be inferred from timing and finger state

    Events are filtered in a CGEventTap, which needs the Accessibility
    permission; every rebuild gets a new ad-hoc signature, so the permission has
    to be granted again

  - Native macOS 13 or later, with no third-party dependencies and no network access
approach: >-
  The code is a Swift package split in two. MuseCore holds every decision as
  plain, testable Swift: parsing touch frames, tracking fingers per touch
  session, deciding whether a scroll may pass, detecting taps, turning finger
  movement into cursor movement, keeping the cursor on screen, recognising Magic
  Mouse devices, and loading settings. The app target is thin glue: a multitouch
  callback that feeds MuseCore, a CGEventTap at the head of the HID event stream
  that drops or lets through scroll and pointer events, the menu bar, and a
  SwiftUI Settings window. Each behaviour was built red-green-refactor, with the
  failing test committed before the code that passes it.
keyDecisions:
  - decision: Keep all logic in a tested core library and the system glue thin
    reasoning: >-
      Private framework callbacks and event taps are hard to test, but the rules
      they apply are not. Moving those rules into MuseCore let every one of them
      be unit tested, and `make coverage` is kept at 100% for that library.
    alternatives:
      - One app target with the logic inside the callbacks (only testable by hand)
  - decision: Infer the event source from touch timing
    reasoning: >-
      A scroll event does not name its device. Muse treats a continuous scroll as
      coming from the Magic Mouse only when the mouse was touched more recently
      than any trackpad and a finger is down (or was within the last second), so
      trackpad and scroll-wheel scrolling always pass.
    alternatives:
      - Filtering every continuous scroll (would break the trackpad)
  - decision: Gate scrolling on the gesture, not the frame
    reasoning: >-
      Fingers do not land or lift at exactly the same time. Scrolling is allowed
      for 0.25 seconds after two fingers were last down, and momentum after
      lift-off passes only if the gesture that started it used two fingers, so
      two-finger scrolls never stutter and one-finger flicks never coast.
    alternatives:
      - Checking the finger count on each event (drops scrolls mid-gesture)
  - decision: Tag Muse's own events
    reasoning: >-
      Cursor moves and clicks that Muse posts carry a marker value, so the event
      tap can tell them from hardware. That is what lets the optical-sensor
      setting block real mouse movement while still letting Muse's own moves
      through, and stops a real button press from being mistaken for a tap.
    alternatives:
      - Pausing the tap while posting events (racy)
  - decision: Post drags when a button is held
    reasoning: >-
      A plain mouse-moved event while a button is down breaks text selection and
      window dragging, so cursor moves are posted as left or right drags when that
      button is held.

Muse is a small, open source macOS utility. It depends on Apple's private
MultitouchSupport framework, so a future macOS update could break it, and it is
built and installed from source rather than shipped as a signed download.

## What's Built

- **Cursor**: One finger on the surface moves the cursor, with speed, acceleration, a dead zone against jitter, and per-axis inversion
- **Scrolling**: Two-finger scrolling and momentum pass through; one-finger scrolling is blocked
- **Tap to click**: An optional quick one-finger tap is a left click, and two quick taps a double click
- **Optical sensor toggle**: Sliding the mouse on the desk can be turned off, so only the touch surface and the trackpad move the cursor
- **Menu bar**: Connection and permission status, pause and resume, Launch at Login, and a hideable icon
- **Settings window**: Every option in a SwiftUI window that stays on top and applies changes as you drag
- **Tooling**: `make install`, `make test`, `make coverage`, `make probe` to list touch devices, and a `--debug` mode that logs finger counts and blocked scrolls

## How It Works

Muse hooks every multitouch device and records which ones are Magic Mice by
their device family. Frames from the mouse update a touch session (current
fingers, the most fingers in this gesture, when two fingers were last down) and
drive the cursor and the tap detector. A CGEventTap sees every scroll and pointer
event before applications do and asks the touch session whether it may pass.

## What's Next

- **Distribution**: A signed, notarised build so the Accessibility permission survives updates
- **Compatibility**: Re-checking the private framework on each new macOS release
