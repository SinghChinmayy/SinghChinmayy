## Current direction

The repository starts with a small, explicit API surface and grows toward an
auditable incident lifecycle:

1. Detect a service signal.
2. Record an incident.
3. Propose a remediation.
4. Require approval.
5. Run the action and verify recovery.

The project is intentionally presented as ongoing work. The repository README
tracks the first backend slice and the evidence expected for each feature.
